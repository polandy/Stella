Who Thomas is: relationship and circle as the second line

When two people share a name, ⌘K and the pickers show a second line under each: the description, or where and when you met. A Thomas with neither shows Nothing yet, even when Stella knows he is Sabine's brother or coaches at the Turnverein. This concept adds those two as further fallbacks. It covers which one wins when there are several, and how the line never names a person or circle the viewer may not see.

Try it

The household has five people called Thomas. Andy and Mia are the two members. Andy keeps Nora Vogt private, and Mia keeps the circle Class 9a private. Switch the viewer and see which lines change.

The rules

The first of these that has something to say is the line. The first two exist today.

  1. Description: what somebody typed to know them by. It is the most deliberate, so it always wins.
  2. Where and when met: Met in Zermatt, 2023. Also typed by hand.
  3. Relationshipnew: Brother of Sabine Keller, as the link reads from Thomas's end, in the viewer's language (relationshipRowLabel). A link to the viewer's own person reads Your brother.
  4. Circlenew: Turnverein Muri · Coach, or just the circle's name when the membership has no role.
  5. Nothing yet, as today.

A relationship ranks above a circle because it names one person. A circle is often large (a whole class, a club), so it tells less about which Thomas this is.

Which relationship, when there are several

  • Only links the viewer can see. A link counts only when the viewer can see both ends (relationshipVisibleTo). Thomas's friendship with Andy's private Nora does not exist for Mia.
  • Only current links. A former one (ex-colleague) says where he was, not who he is, and it can mislead.
  • Never another namesake. A link whose other end is itself a name shared on the list is skipped: Father of Thomas is no help choosing between Thomases.
  • Then by category: family, romantic, social, professional, other. Family is the most stable and the easiest to recognise. Within a category, by the type's order, then by the oldest link, so the line doesn't jump when a new link is added.

Which circle, when there are several

  • Only circles the viewer can see (membershipVisibleTo): Mia's private Class 9a never shows up for Andy.
  • Only current membership in a circle that is not archived, and a membership whose end date has not passed.
  • The most specific first. If he is in School Muri and in its sub-circle Class 9a, the line says Class 9a. After that, a membership with a role ranks first, then the most recent start date, then the circle's name.

Why it has to be worked out on the server, per viewer

The pickers work out the line in the browser today, from the people list the shell loads ((app)/+layout.server.ts). Description and meeting place live on the person, so that is safe. A relationship and a circle are separate records with their own visibility. If the browser got them to choose from, it would receive links it may not see. So:

  • A domain use-case, contextHintsFor(deps, viewer), reads the current, visible links and memberships, scoped through src/lib/server/access/. It covers only people with no description and no meeting place, because the line never gets that far for anyone else.
  • A pure function ranks the candidates (the rules above) and keeps the first three relationships and the first circle for each person. It is test-first in src/lib/people/.
  • The people list gains an optional context field carrying just those candidates. Each one is a type key or label, a direction, the other person's id and name, or a circle's name and role. A few hundred people at most, so the payload stays small.
  • tellApart stays pure and in the browser. It already knows which names are shared, so it picks the first relationship candidate whose other end is not a namesake. That is why the server sends three, not one. Distinction gains relationship and circle kinds, and describeDistinction words them.
  • The refusal of an ambiguous @Thomas (resolveForAudience) names the candidates with the same line. It only ever goes to the author, so the author's own view is the right one.

Nothing is stored. The line is always derived from what the viewer can see right now, so ending a link or making a circle private changes it on the next page load, with nothing to keep in sync.

What does not change

  • Only namesakes get a second line. Someone called Thomas with no other Thomas in the household still shows a single line.
  • The relationship form still fills a new person's description from the link (Child of Hans Meyer).

Decided

  1. Met before relationship. Met in Zermatt, 2023 was typed by hand to tell him apart, and it reads the same for everyone in the household. A relationship line can differ between Andy and Mia.
  2. The viewer's own relationships read Your brother. The line is worked out per viewer anyway: Mia sees the same link as Brother of Andy.
  3. The clean-up list fills the description in from the line. A row whose person has a relationship or circle line gets it as the field's value, kept only when the user saves. Because a description is stored for everyone, it always takes the name form (Brother of Andy), never Your brother. The list itself stays as it is: it gathers people with no description and no meeting place, whether or not a relationship gives them a line, since a link can end or be made private and a description stays.
  4. Only namesakes get a second line. Someone with a first name alone and no namesake keeps one line; the clean-up list is where they turn up. It can be widened later.
