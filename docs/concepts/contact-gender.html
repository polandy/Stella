Concept · Contacts

Gender and pronouns, edited where they are read

Stella already stores a gender and pronouns for each contact and uses the gender to name relatives (aunt rather than aunt or uncle). But only an import can set them. This mockup adds them to the profile card, where the rest of a person's facts live.

Prototype

Rosa's profile

Click the Gender row in the profile card. Pick one of three options and add pronouns if you like. The worked-out relatives on the left update as you choose, so you can see what the field changes. Enter saves and Esc cancels, just like the name and the description.

Decisions in this mockup

What the design settles

Settled

One row, not two

Gender and pronouns share one row, Female · she/her, and one editor. They are read together, so they are edited together. The row sits at the top of the profile card, above contact details.

Settled

Three options, nothing else

Three presets are stored as female, male and diverse and shown translated; there is no free-text gender. Only female and male make relatives gendered; Diverse and nothing on record name them neutrally, which is how src/lib/kinship already behaves.

Settled

Pronouns are free text

Suggestions follow the chosen gender and the UI language (sie/ihr, she/her, …), but any text is allowed. Pronouns never change kinship wording.

Settled

Empty is a real answer

With nothing on record the row says so quietly, and relatives are named neutrally. Remove in the editor clears both fields.

Settled

Pronouns only on the profile

The header keeps name, description and the meta line. It is already full on a phone, and in a family CRM you mostly know the people anyway.

Settled

New contact asks for gender, not pronouns

One optional chip row under the names. It works offline too: the contact.add command gains an optional gender, so older queued commands without it still apply.

Settled

Imported “O” becomes Diverse

Monica and vCard imports have dropped O (other) so far, because there was nowhere for it to go. Now it maps to diverse.

Settled

Pronouns are kept as typed

sie/ihr stays sie/ihr in the English UI. Only the suggestions follow the UI language, because free text cannot be translated consistently.

Settled

Unknown old values read as not on record

A value other than the three (say, from an old archive) shows as Not on record and is replaced on the next save. The domain accepts only female, male, diverse or nothing.
