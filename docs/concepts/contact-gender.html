Concept · Contacts

Gender, edited where it is read

Stella already stores a gender for each contact and uses the gender to name relatives (aunt rather than aunt or uncle). But only an import can set them. This mockup adds them to the profile card, where the rest of a person's facts live.

Prototype

Rosa's profile

Click the Gender row in the profile card. Tap one of three options, and it is saved at once. The worked-out relatives on the left update as you choose, so you can see what the field changes. Esc closes the editor without a change.

Decisions in this mockup

What the design settles

Settled

No pronouns

Stella never uses pronouns in its own wording, and no import fills them, so the field would stay empty. The pronouns column stays in the schema, unused and untouched, so archives and migrations do not change.

Settled

Three options, nothing else

Three presets are stored as female, male and diverse and shown translated; there is no free-text gender. Only female and male make relatives gendered; Diverse and nothing on record name them neutrally, which is how src/lib/kinship already behaves.

Settled

One tap saves

The row opens three chips. A tap saves and closes, and tapping the chosen one again clears it. With nothing on record the row says so quietly, and relatives are named neutrally.

Settled

New contact asks for gender too

One optional chip row under the names. It works offline too: the contact.add command gains an optional gender, so older queued commands without it still apply.

Settled

Imported “O” becomes Diverse

Monica and vCard imports have dropped O (other) so far, because there was nowhere for it to go. Now it maps to diverse.

Settled

Unknown old values read as not on record

A value other than the three (say, from an old archive) shows as Not on record and is replaced on the next save. The domain accepts only female, male, diverse or nothing.
