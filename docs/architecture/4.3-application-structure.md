## 4.3 Application structure

A conventional SvelteKit layout with a clear server/domain separation:

```
src/
  lib/
    server/
      db/            # drizzle schema, client, migrations
      auth/          # sessions, password (argon2), oidc (relying party)
      domain/        # use-cases: contacts, relationships, notes, media, feed…
      access/        # central visibility/ACL enforcement (see 3.7)
      media/         # sharp pipeline, storage paths
      search/        # FTS5 sync + query
      i18n/          # say(locals, key): a message in the language of the request
      commands/      # the edge's half of commands: parse off the wire, receive a phone's batch
      immich/        # Immich adapter: env config, http-gateway.ts (the only fetch to Immich; the
                     #   key never leaves it), the face routes' answers, the demo/fake gateway;
                     #   the port and use-cases live in domain/immich/
      config.ts      # env parsing/validation (valibot) — the only $env reader
    commands/         # pure: the command vocabulary shared by the phone and the server (§4.11.2);
                      #   server/domain/commands/ applies one once, server/commands/ is the wire edge
    i18n/             # locales, message catalogues (en/de), translator, context — all UI copy
    errors/           # TranslatableError: a domain error carrying its message untranslated
    kinship/          # pure: derives the relatives nobody entered (§2.4.1)
    suggestions/      # pure: what to *offer* — rules say what follows, engine.ts applies the
                      #   universal suppressions centrally, reasons are Phrases (§2.4.1)
    sync/             # pure: pending-work counting behind the shell's activity indicator
                      #   (pending-work.ts store, trackPending / whilePending / reportNavigation)
    shell/            # pure: when a phone's top bar slides away on scroll (top-bar.ts)
    contacts/         # pure: the person page's vocabulary — the cards' anchors (sections.ts),
                      #   the jump bar's links and which card is being read (jump-bar.ts)
    onboarding/       # pure: whether Home shows the welcome card, which steps it offers
                      #   and which are done (welcome.ts)
    surnames/         # pure: last-name batches on screen — which rows a held batch hides, who
                      #   becomes a namesake; held-names.svelte.ts adapts it to the undo window
    motion/           # pure: expand/collapse motion (motion.ts: easing, reveal frames, when a
                      #   height glides); motion.svelte.ts is the adapter — transition:reveal,
                      #   use:glide, the cross-fade Swap.svelte builds on (docs/05 §5.11)
    menu/             # pure: toolbar-menu decisions — the Filter pill's count and highlight,
                      #   arrow-key movement
    stream/           # pure: the household-stream filter — kinds, the ?kind=/?by= codec,
                      #   what the chips show
    pwa/              # pure: install/offline policy — manifest, cache rules, icon geometry,
                      #   reachability protocol, the outbox's states. src/service-worker.ts,
                      #   install.svelte.ts, reachability.svelte.ts, outbox.svelte.ts and
                      #   outbox-store.ts are the adapters: browser APIs, never a decision
    immich/           # pure: the Immich links the browser sees — web deep link, face-thumbnail
                      #   URL, the name matcher for *Find your people* (match.ts), which ties
                      #   offer *Together* and which chips show (together.ts)
    graph/
      model/          # pure: GraphModel, buildEgoNetwork, expandNode, findConnectionPath, applyFilters
      layout/         # pure: arrangements as positions (family tree, groups by circle) and the
                      #   density and legibility numbers the canvas is drawn at
      keyboard.ts     # pure: which key steps to whom on the map
      phone-map.ts    # pure: a phone's map on a person's page — preview / enlarged / full
                      #   screen, which view follows which tap
      cytoscape/      # rendering adapter: Cytoscape confined here, lazy-loaded; no domain logic
    components/       # Svelte UI components (design system): Button, Icon + the icons.ts
                      #   registry, Avatar, Section, EmptyState, CommandPalette, MenuButton,
                      #   Toast + RemoveButton, InlineEdit, …
      graph/          # the map: GraphExplorer wires state to the canvas; its parts (GraphCanvas,
                      #   GraphFilterMenu, GraphArrangeMenu, GraphFindField, GraphNodePeek /
                      #   GraphGroupPeek, GraphPathPrompt) only render
      person/         # the person page's cards, one per section; the route only lays them out
    design/tokens.ts  # the token table in TS — the only place that builds a colour token string
    stores/           # client state (theme, ui)
  routes/
    (auth)/           # login, sso callback, invite accept, logout
    (app)/            # authenticated app shell
      contacts/…      # list, [id] profile (load.ts + actions/ grouped per card), new
      graph/…
      feed/…
      reminders/…
      search/…
      settings/…
    api/              # +server.ts JSON endpoints (graph data, upload, search, commands)
  hooks.server.ts     # session resolution, language of the request, security headers
  app.css             # tailwind + the three token layers: Catppuccin flavour → surfaces → semantic
static/               # manifest, icons, offline shell
```

**Principles:**

- **Ports & Adapters.** The domain owns narrow interfaces (ports); `db/` and other
  infrastructure implement them (adapters); use-cases receive their collaborators
  (repository, `Clock`, `IdGenerator`) via an explicit `deps` argument; the SvelteKit
  edge is the only composition root that wires concretes. Pure logic takes no
  dependencies. Full convention: [`08-coding-guidelines.md` §8.3](../08-coding-guidelines.md).
- All data access goes through `lib/server/domain/*`, which calls `lib/server/access`
  for every read/write. **No route or component queries the DB directly.** ACL rules
  (§3.7) live in exactly one place.
- SvelteKit **form actions** for mutations (progressive enhancement, works without JS);
  **`+server.ts`** endpoints for JSON needs (graph data, search-as-you-type, uploads).
- **Load functions** are server-side and already visibility-scoped.
